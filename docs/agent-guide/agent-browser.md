# Agent browsers (LKM-212)

Each chat or background agent gets a private WebKit page when it first calls a preview tool. The page is a `WKWebView` owned by the native host, attached outside the window without focus. It uses the same `TreziPreview` and `TreziAgent` content worlds as the visible preview. The host discards all page-to-app IPC from an agent browser. Media permission requests are denied. Main-frame navigation stays on the assigned local dev-server origin.

`open_preview`, `reload_preview`, and the `preview_*` observers default to that page. Its route, scroll, viewport, console and animation speed belong to the agent session. It loads the live checkout served by Trezi's dev server; private worktree edits must land first (`land_now`) to appear there. Its identity includes a session-specific suffix, navigation count, document start and the live HEAD sampled at navigation. Three pages may exist at once. They close after two minutes idle and when explicitly released. A fourth agent receives a limit error. `reload_preview` loads the agent page again (`AgentBrowser.open(path, { reload: true, hard })`; `hard` clears WebKit's caches first). A failed load in an agent page answers only the agent's tool call; it never reaches the user's activity or the preview's load-error UI.

`target: "user"` reads or changes the visible preview. Navigation, viewport and speed changes require five seconds without user input in Trezi. Agents should use it only when the user asks to see the page or the result needs visible rendering. Offscreen snapshots use `WKWebView.takeSnapshot`; Liquid Glass/backdrop and some GPU effects may not paint. A check requiring those effects must be named as a visible-rendering check.

`engine: "chromium"` is an optional adapter slot. The agent browser interface is shared across engines; the Chromium factory can be registered when the external `agent-browser` CLI and Chrome for Testing are installed. WebKit is always available with Trezi. A missing adapter returns an explicit error. No Chromium download runs as part of Trezi's normal build or preview.

Vercel agent-browser remains required for browser verification during UI changes. Trezi's provider helpers put `bin/managed/agent-browser` first on PATH (`src/main/backends/managed-browser-path.ts`: the bundle's `__dirname` is `out/native`, so `../../bin/managed`; a source run uses `../../../bin/managed`) and append the directory of the helper's own Bun so the wrapper's `env bun` shebang resolves under the helper's system-only launch PATH.

PATH alone is not the route (LKM-269). A provider shell run as a login shell (Codex's default) lets macOS path_helper and the user's profile reorder PATH, so a global `/opt/homebrew/bin/agent-browser` can win. The route is the explicit, app-owned absolute path to the wrapper, `managedBrowserWrapper(base)`: the same two bases, only if the file exists and is executable, exported as `TREZI_AGENT_BROWSER`. The helper sets it in its own environment at start (`provider-helper-entry.ts`), and each provider re-applies it on every turn, so a reused or resumed helper keeps it:

- **Codex** (`managedBrowserCodexConfig`, merged in `codex.ts` `openThread`, which first turns and resumes both use): `shell_environment_policy.set` with the managed PATH and `TREZI_AGENT_BROWSER`, `allow_login_shell=false` (locally parsed by standalone CLI 0.159.1 and bundled CLI 0.160.1) and a PreToolUse command hook, `bin/trezi-browser-guard.mjs`, beside the Git guard.
- **Claude** (`claude.ts`): the query's `env` carries the same two variables, and the existing PreToolUse Bash hook calls `managedBrowserRefusal`. The absolute route avoids depending on Claude Bash preserving PATH; the dispatch fixture checks the supplied environment and hook, without making a live provider call.
- **Policy** (`bin/trezi-browser-policy.mjs`, shared): the only absolute path allowed is Trezi's wrapper (`"$TREZI_AGENT_BROWSER"` or its literal path). A bare `agent-browser` (also behind `env`, `bash -c`, `npx`…), any other absolute or relative path to a CLI, reassigning `TREZI_AGENT_BROWSER`/`PATH` for it, the wrapper's forbidden flags (`--headed`, `--executable-path`, `--profile`, `--cdp`, `close --all`…) and a system Chrome app path are refused with the way back. `command -v`, `which` and `echo` stay allowed. The wrapper still enforces the flags itself.
- **Errors**: the wrapper exits 2 for a route or policy refusal and 3 for a missing dependency, with `dependency: vercel-cli` or `dependency: headless-shell` and install guidance. A route problem never tells the user to reinstall a browser, and a global CLI on PATH is only the engine behind the wrapper, never a managed-verification pass. There is no WebKit, `preview_evaluate`, headed or system-Chrome fallback.
- **Tests**: `test/managed-browser-path.mjs` runs real `/bin/zsh -c` and `-lc` (a throwaway ZDOTDIR mimics the login-shell PATH reorder) against the bundle and source bases with a global CLI earlier on PATH; `test/managed-browser-provider.mjs` checks Claude and Codex first and resumed turns, replaying the Codex config through the real SDK into a fake `codex` binary; native smoke `managed-agent-browser` repeats the shell check beside the unchanged focus evidence.

Compatibility evidence (2026-10-17): the [tagged Codex 0.159.1 handler](https://github.com/openai/codex/blob/rust-v0.159.1/codex-rs/core/src/tools/handlers/unified_exec/exec_command.rs#L499-L508) maps `exec_command` to the canonical hook name `Bash` with a `command` field. Parsing the config is insufficient: [hook discovery](https://github.com/openai/codex/blob/rust-v0.159.1/codex-rs/hooks/src/engine/discovery.rs#L634-L687) ignores optional inline hooks until their exact normalized identity is trusted. `trustedCodexHookOverrides` supplies hashes for only Trezi's combined Git/browser session-flag groups, recomputed after indexing them. A single inline `hooks.state` value preserves the dotted synthetic source filename; the CLI override parser does not interpret quoted dotted path components. No blanket hook-trust bypass or persistent user-config edit is used. Provider initialization fails closed unless the locked SDK is 0.160.1 and any explicit CLI override reports exactly 0.159.1 or 0.160.1; unsupported versions require a passing local dispatch regression before extending the allowlist.

`test/managed-browser-dispatch.mjs` drives the actual bundled SDK/CLI against loopback Responses and Messages API fixtures, with disposable HOME/config directories, fake keys and temporary marker scripts instead of browsers. Installed Codex 0.159.1, bundled Codex 0.160.1 and installed Claude 2.1.285 passed managed execution and denied global execution on first/resumed sessions, using source/bundle layouts including spaces. The combined Codex config also denies raw Git pushes and leaves an unrelated untrusted user hook disabled. Optional `TREZI_DISPATCH_CODEX_BIN` and `TREZI_DISPATCH_CLAUDE_BIN` select additional local executables. These checks do not demonstrate live subscription behavior or native focus preservation; those remain separate acceptance evidence.

A missing Codex guard fails provider setup. Nested `command` execution receives route checks, while `-v/-V` may inspect the route. Browser commands in shell substitutions or embedded shell programs are refused with guidance to invoke the managed route separately. This bounded policy is not a general shell sandbox.

This wrapper uses the installed CLI with a dedicated `chrome-headless-shell` executable, private HOME, temporary directory and profile for each named session, a private config, and `--headed false`. It refuses a system Chrome fallback, external CDP attachment and overrides that could expose a GUI browser. If the CLI or headless shell is missing, it reports the dependency instead of installing it or substituting WebKit. The CLI's daemon can be reused within a session and is given a two-minute idle timeout. The optional in-process Chromium adapter remains unregistered; the managed CLI is the required Chromium path.

Native smoke records passive frontmost PID, key window, first responder, activation notifications and cursor coordinates around private WebKit operations. A separate managed-CLI fixture checks the actual Chromium path. No focus restoration runs after browser commands.

The host commands are `agentBrowserCreate`, `agentBrowserOpen`, `agentBrowserSpeed` and `agentBrowserClose`; Bun owns session reuse and idle cleanup in `src/main/agent-browser.ts`. The visible preview remains the only source of editor selection and overlay IPC. Native smoke `agent-preview` checks two independent sessions, the cap, an offscreen screenshot, and that the visible URL, width, scroll, selection and focus remain unchanged.

`preview_interact` (LKM-230) uses the agent page: `click` (a `selector` plus `index`, a `source` stamp or `x`/`y`), `type` (`text`, `clear`), `press` (`key`, optionally on a `selector`), `hover`, `scroll` (`deltaX`/`deltaY`, `to: "top"|"bottom"` or into view), `select` (`option` by value or label) and `wait` (a `selector`, `hidden`, `text` or `networkIdle`, up to 15 s). `target: "user"` is refused: interaction never drives the user's preview. The page side is `src/preview/agent-interact.ts` in the isolated world; it synthesizes DOM events (so click activation, input and key handlers run, but CSS `:hover` does not apply) and refuses file inputs, `download` links, links and forms that leave the dev server origin, and forms posting to other hosts. The host is the backstop: `agentPolicy` in `src/native/PreviewPlatform.swift` blocks off-origin main-frame navigation, external form submission, new windows and downloads (including responses WebKit cannot show) for `agent:` views only, and emits `agent-navigation` events (`start`, `blocked`, `failed`) that `src/main/agent-browser.ts` keeps as `loading` and `notices`. `src/main/agent-interact.ts` validates the request, waits up to 10 s for a navigation the action started, and answers JSON with `ok`, the resulting `url`, `navigated`, any `blocked` notices and the console errors since the action, plus a 480 px JPEG unless `screenshot: false`. Network idle counts the page's `fetch`/XHR through a page-world counter installed in agent pages only. Fetches to other hosts are not blocked, and there is no per-user allowance for leaving the origin yet. Native smoke `agent-interact` drives `filter.html` in the fixture (filter click by selector and by source, type, select, hover, scroll, waits, a same-origin form) and checks each refusal and host block, and that the user's preview is unchanged.
