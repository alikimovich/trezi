# LKM-223 — onboarding and provider authentication research

Research checked 2026-10-09. This is the Phase 0 decision record and Phase 1 design input, not an implementation authorization. Provider policy and preview features can change; recheck the linked primary sources before Phase 2.

## What Zed actually does

Zed has **two different agent paths**, so “Zed signs in to Claude and Codex” is incomplete. Its built-in Zed Agent uses Zed-configured providers. Its External Agents run as separate ACP processes and normally own their own authentication, configuration, and billing. Zed's [External Agents guide](https://zed.dev/docs/ai/external-agents) says the Claude Agent can authenticate with an API key or Claude Code where supported, and Codex can use ChatGPT or API-key auth according to the installed agent. Zed's provider keys do not automatically become ACP-agent credentials. The [Zed subscription matrix](https://zed.dev/docs/ai/use-an-existing-subscription) lists Claude Pro/Max only through the external Claude Agent or CLI, while ChatGPT Plus/Pro also has a Zed Agent provider path.

Zed's [Claude ACP adapter](https://github.com/agentclientprotocol/claude-agent-acp) (formerly at `zed-industries/claude-code-acp`; its README describes the official Claude Agent SDK underneath) and [Codex ACP adapter](https://github.com/zed-industries/codex-acp) are distinct agent processes. The latter explicitly wraps Codex CLI and advertises ChatGPT and API-key methods; it is not Zed extracting tokens from `codex login`. The former invokes the Claude Agent SDK and its CLI runtime; it is not simply an interactive terminal shell. Zed can also run either CLI directly in a terminal thread. The [Zed ACP announcement](https://zed.dev/blog/claude-code-via-acp) confirms the protocol boundary.

Separately, Zed [announced direct ChatGPT subscription sign-in for its built-in agent](https://zed.dev/blog/chatgpt-subscription-in-zed) in May 2026. That browser handoff is a Zed/OpenAI integration, not evidence that any app may reuse Zed's OAuth client or Codex CLI credential cache. Zed stores **its own provider API keys** in the [system keychain](https://zed.dev/docs/ai/use-api-access); external agents keep their own credentials. Zed's Claude Agent has no direct Claude subscription provider path for Zed Agent. Zed account sign-in itself is a [separate GitHub OAuth flow](https://zed.dev/docs/authentication).

## Supported paths and boundaries

| Provider/path | Supported use and constraints | Credential owner, expiry, recovery |
| --- | --- | --- |
| Claude Code `claude auth login` | Official browser login for Claude.ai subscription or Console (including Console OAuth or API billing). `claude auth status` returns JSON and exit 0/1; `claude auth logout` removes its login. This is a supported **Claude Code** flow, including its own interactive use. It is **not** blanket permission for Trezi to offer Claude.ai subscription login through its third-party Agent SDK product. [CLI reference](https://code.claude.com/docs/en/cli-reference), [authentication](https://code.claude.com/docs/en/authentication) | Claude Code owns refresh and storage. On macOS it uses Keychain, with a documented mode-0600 file fallback for some Keychain failures. Trezi must query status only, not read either store. Re-login after unrecoverable expiry. |
| Claude Agent SDK with Console API key | Official third-party product route: [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview) explicitly directs unapproved third-party developers to API-key authentication. Claude API keys are billed through Console and can expire or be revoked. Cloud provider credentials are also supported where configured. [Claude API authentication](https://platform.claude.com/docs/en/manage-claude/authentication) | Prefer a secure app-scoped Keychain item if Trezi collects a key. Never pass it in argv, transcript, project files, or logs. No automatic refresh for a static key; user replaces or revokes it after a 401. A CLI-managed Console login is an alternative only if the exact SDK/CLI use is validated before Phase 2. |
| Claude subscription via Agent SDK / `claude -p` | Current [Anthropic help update, 2026-10-07](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) says third-party apps still draw from subscription limits. The [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview) simultaneously says third-party developers cannot offer claude.ai login or rate limits **unless previously approved**. These statements have different policy scope and are unresolved for Trezi; use the stricter product rule until Anthropic gives approval. | Claude Code may refresh its own OAuth login, but Trezi must neither export its token nor proxy it. A `claude setup-token` value is a sensitive long-lived token intended for scripts, not an onboarding shortcut. [Credential precedence](https://code.claude.com/docs/en/authentication). |
| Claude device/browser flow | Claude Code documents browser login, including the CLI's `/login` and `claude auth login`. It does not publish a general-purpose third-party Claude.ai device grant for Trezi. Anthropic's **different** `ant` API CLI supports browser OAuth and `--no-browser` code return for Console API access; that is not a Claude subscription login. [Claude Code CLI](https://code.claude.com/docs/en/cli-reference), [`ant` auth](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/authentication). | The CLI or `ant` owns its credentials and refresh. Avoid presenting `ant` sign-in as a Trezi subscription path. |
| Codex CLI `codex login` | Official ChatGPT browser login; `codex login --device-auth` is beta and needs device-code permission. `codex login --with-api-key` takes the key from **stdin**, not argv. `codex login status` and `codex logout` are documented. [Codex authentication](https://learn.chatgpt.com/docs/auth) | Codex caches in `~/.codex/auth.json` or OS credential store, configurable as `file`, `keyring`, `auto`, or `ephemeral`; it refreshes ChatGPT tokens during active use. Trezi must never read the cache. |
| Codex app-server | Official embedding surface: `account/read` reports status without token material; `account/login/start` supports ChatGPT browser, device code and API key; `account/login/cancel` and `account/logout` are documented. This is the preferred native orchestration for Codex sign-in. [App-server protocol](https://learn.chatgpt.com/docs/app-server) | Codex manages its own login for the native browser/device modes. Do not use experimental externally managed `chatgptAuthTokens` to copy CLI tokens. Re-read account on app restart; handle cancelled/failed notifications. |
| Codex SDK / API key | Official Codex SDK runs the Codex CLI and normally inherits its login. An OpenAI API key uses separate Platform billing and can be supplied to the CLI via stdin or app-server's API-key RPC over private stdio, never argv. [Codex auth](https://learn.chatgpt.com/docs/auth), [app-server](https://learn.chatgpt.com/docs/app-server) | CLI/app-server owns stored credentials when using its login flow. For app-owned keys, keep only in scoped Keychain, offer clear/remove, and require replacement on revocation. |
| Sign in with ChatGPT for open-source local apps | OpenAI now documents a **separate** dynamic-registration flow for local open-source apps with optional plan-use scope, issued client IDs, PKCE, and app-owned token storage. It can feed Codex app-server, but adds a second token lifecycle. Paid or remotely hosted apps need to [request access](https://developers.openai.com/siwc/token-sharing-open-source). Use only if Trezi deliberately adopts that program, not by borrowing another client ID. [Overview](https://developers.openai.com/siwc/token-sharing-open-source), [Codex app-server bridge](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) | The app must protect profiles, verify scopes, refresh tokens, handle revocation, and follow [OpenAI UI/UX guidelines](https://developers.openai.com/siwc/ui-ux-guidelines). More responsibility than Codex-managed auth. |

Anthropic's [SDK branding guide](https://code.claude.com/docs/en/agent-sdk/overview) allows “Claude Agent” and “Claude” in a labeled agent menu, with restrictions on implying Anthropic endorsement. OpenAI's [ChatGPT plan UI guidance](https://developers.openai.com/siwc/ui-ux-guidelines) applies if Trezi later chooses the separate Sign in with ChatGPT program. In the proposed Codex-managed flow, label the action “Sign in to Codex with ChatGPT” and attribute browser pages to OpenAI; do not imply Trezi is an official provider client or that a ChatGPT subscription pays for Claude. Provider terms and plan availability remain the provider's, and this document does not assert commercial authorization outside the cited paths.

## Recommendation for Trezi

1. **Codex:** use Codex app-server's managed ChatGPT browser flow and status/logout RPCs. Offer its device-code fallback only when enabled. Codex owns credentials and refresh; Trezi receives status metadata and login URL/code only. This meets the in-app start/status experience without handling tokens.
2. **Claude:** use the existing Claude Agent SDK with a user-supplied **Claude Console API key** stored by Trezi's service in an app-scoped macOS Keychain item. Explain separate API billing before the secure entry field. Offer a link to create a key and a clear-key action. Do not offer a Claude.ai subscription sign-in button until Anthropic explicitly approves Trezi's third-party product use. Existing CLI-managed Console auth may be recognized only if SDK behavior and billing are validated as part of Phase 2. The current Trezi `setup-token` path deserves removal or a policy review in a separate implementation issue; Phase 1 does not mutate it.
3. The two cards use the same visual grammar but **different honest verbs**: “Sign in with ChatGPT” for Codex, “Connect Claude API key” for Claude. A generic “Sign in to Claude” would promise subscription parity we cannot currently support.

This recommendation is intentionally narrower than the current help-center statement about technical subscription usage. It avoids token scraping, unauthorized OAuth client IDs, and relaying subscription tokens. If Anthropic clarifies that Trezi may offer Claude.ai login, revise this decision and its UI before implementation.
